# q5: Among players with at least one NBA championship, what is the most championships won by any player of each nationality?
## Query contract
**Natural language:** Among players with at least one NBA championship, what is the most championships won by any player of each nationality?

**Reference SQL**
```sql
SELECT nationality, MAX(nba_championships) AS max_championships FROM player WHERE nba_championships >= 1 AND nationality != '' GROUP BY nationality
```

**QuWARTS compiled SQL**
```sql
SELECT nationality, MAX(nba_championships) AS max_championships FROM player WHERE nba_championships >= 1 AND nationality != '' GROUP BY nationality
```

The SQL contracts are equivalent unless the two SQL blocks visibly differ. Therefore, documented failures below are downstream of intent/compilation.

### Why QuWARTS differs
- **Pipeline stage:** Attribute meaning and category resolution
- **Root cause:** The extractor matched nearby sports counts to the NBA-title field and did not resolve nationality variants.
- **Why the system made this choice:** The raw scalar gate checks that a championship value is numeric, but it does not check the sport or event that the number describes.
- **Why the checks did not catch it:** Six Stanley Cups and cited years appear in source text and pass number and span checks. The pilot has no semantic bound for NBA titles.
- **Why this query failed:** Wrong title counts become group maxima, while nationality variants form different groups. One gold mismatch also comes from the evaluator keeping an empty string in a numeric comparison.

**What we saw in the run**
- Dominican and Nigerian-American are replaced by Dominican Republic and Nigerian; Yugoslav is an additional unmatched group.
- Canadian is reported as 6 rather than 1, indicating a wrong championship count on at least one retained record.
- The Canadian=6 row is Larry Robinson, a hockey player whose six Stanley Cups were extracted as NBA championships; Dino Rađa becomes Yugoslav=2 after two cited years are interpreted as two NBA titles.
- Gold reports an empty American maximum because an empty championship string survives the mixed-type SQLite predicate and dominates MAX; QuWARTS reports the semantically plausible numeric 6 but is still penalized against that evaluator result.

### Why DocETL differs
- **Pipeline stage:** Map reliability and semantic number checks
- **Root cause:** Some Map rows were skipped or incomplete, and the number schema did not verify that a value was an NBA-title count.
- **Why the system made this choice:** Every source document is sent to the Map step, but skip-on-error is enabled. The prompt asks for one number and one nationality with no evidence test.
- **Why the checks did not catch it:** A value such as 9 is a valid number even when it is the wrong fact. Missing Map rows do not cause the whole query to fail.
- **Why this query failed:** Missing rows remove nationality groups, while a false title count sets the American maximum. Exact nationality variants create more group errors.

**What we saw in the run**
- The q5 extraction contains only 116 rows; 65 nationalities are empty and 81 championship values are -1.
- The American maximum is 9, although gold's evaluator result is the empty-string edge case; Nigerian-American is 2 instead of 1.
- All player source documents were sent to the q5 Map step, but OG Anunoby (British) and Giannis Antetokounmpo (Greek and Nigerian) are absent from its 116-row output. The Map operation allows failed rows to be skipped. Steve Kerr supplies the false American maximum of 9.
- British and Greek and Nigerian are missing, while Croatian, Dutch, Greek, and Slovenian are extra groups.
