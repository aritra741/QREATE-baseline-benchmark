# q1: How many players are there for each nationality?
## Query contract
**Natural language:** How many players are there for each nationality?

**Reference SQL**
```sql
SELECT nationality, COUNT(*) AS player_count FROM player WHERE nationality != '' GROUP BY nationality
```


### Why QuWARTS differs
- **Pipeline stage:** Semantic mapping and extraction coverage
- **Root cause:** The semantic view did not learn one stable nationality vocabulary, and many nationality cells were never extracted.
- **Why the system made this choice:** QuWARTS only applies value changes that can be tied to an induced mapping or evidence. This avoids unsupported rewrites, but compound labels remain unchanged when no safe map is found.
- **Why the checks did not catch it:** Country names and demonyms are valid supported text. The checks measure coverage and source support, not whether two labels should be one group.
- **Why this query failed:** Compound nationalities split into new labels, while missing cells reduce the American group. GROUP BY then treats each surface as a different nationality.

**What we saw in the run**
- The materialized output counts 82 American players versus 116 in gold.
- Gold labels such as American-born naturalized Azerbaijani, Dominican, Dutch, and Nigerian-American are absent while Azerbaijan, Dominican Republic, Netherlands, and Nigerian appear.
- The output has 24 groups versus 22 in gold: six gold groups are missing, eight unmatched labels are added, and the American count is wrong.

### Why DocETL differs
- **Pipeline stage:** Map output validation
- **Root cause:** Structured model replies were accepted as nationality text, and there was no nationality resolver after extraction.
- **Why the system made this choice:** The output schema declares nationality as text. It does not require a plain scalar or a known nationality label.
- **Why the checks did not catch it:** A JSON object serialized as text still passes the string type. Row count checks also do not test whether each text value is a clean category.
- **Why this query failed:** Malformed payloads become literal GROUP BY keys, while shortened compound nationalities create more missing and extra groups.

**What we saw in the run**
- The q1 extraction has all 141 document rows, but five nationality values are empty and the American group is 102 versus 116 in gold.
- Eight extra groups are serialized JSON or unrelated structured content, including a five-row literal {"nationality": "American"} group and long QAPage/player-profile objects; Azerbaijan and Nigerian are two additional taxonomy substitutions.
- American-born naturalized Azerbaijani is shortened to Azerbaijan, and Cameroonian-American and Greek-American are missing as exact groups.
