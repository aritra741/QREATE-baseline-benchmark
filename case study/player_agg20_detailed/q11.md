# q11: How many players aged 20 to 40 are there for each nationality?
## Query contract
**Natural language:** How many players aged 20 to 40 are there for each nationality?

**Reference SQL**
```sql
SELECT nationality, COUNT(*) AS player_count FROM player WHERE age BETWEEN 20 AND 40 AND nationality != '' GROUP BY nationality
```

**QuWARTS compiled SQL**
```sql
SELECT "t2"."nationality", COUNT(*) AS "player_count"
FROM "player" AS "t2"
WHERE (("t2"."age" >= 20 AND "t2"."age" <= 40) AND "t2"."nationality" != '')
GROUP BY "t2"."nationality"
```

The SQL contracts are equivalent unless the two SQL blocks visibly differ. Therefore, documented failures below are downstream of intent/compilation.

### Why QuWARTS differs
- **Pipeline stage:** Age calculation
- **Root cause:** The QuWARTS table contains old age values instead of the players' ages in 2026.
- **Pipeline behavior behind it:** The working table stores age, but it does not store birth date or the date used for the age calculation. It can therefore keep an age stated in an older article.
- **Why validation allowed it:** An old age from an article is still a normal number. A type check cannot tell whether it is the person's age in 2026.
- **How it affected the result:** Old ages let some older players pass the 20 to 40 rule. Missing ages removed other players, and nationality names split more groups.

**What I found in the final and working tables**
- Age is missing from 91 of 160 rows. Nationality is missing from 53 rows.
- Seven gold nationality groups are missing and six country/demonym variants are extra.
- Saved validation records show Tim Duncan with extracted age 34 and Kobe Bryant with 35. Their benchmark 2026 ages are 50 and 47, so both wrongly pass the 20 to 40 filter.
- American is undercounted 49→40 and French 2→1.

### Why DocETL differs
- **Pipeline stage:** Age calculation and missing values
- **Root cause:** The DocETL table contains old age values and leaves many other ages unknown.
- **Pipeline behavior behind it:** The instruction requests one age number but does not require a birth-date calculation or store the date used for that calculation.
- **Why validation allowed it:** The old ages looked like normal numbers. Players with an unknown age did not appear in the displayed result.
- **How it affected the result:** The final table has no -1 age. The 20 to 40 rule removed those rows. Wrong ages still changed which players passed, and different nationality names caused more errors.

**What I found in the final and working tables**
- The intermediate player table has 49 of 133 ages marked as missing and 45 empty nationalities. The age rule removes the missing ages, so no -1 appears in the final table.
- Four gold groups are missing and four unmatched groups are added.
- Old or unrelated ages move older players into the allowed range. Examples are Mark Price 61→36, Magic Johnson 66→36, and Michael Jordan 62→38. The intermediate table also has 49 unknown ages, and the final filter removes all of those rows.
- American is close but low (49→48), French is 2→1, and Greek is overcounted 1→2.
