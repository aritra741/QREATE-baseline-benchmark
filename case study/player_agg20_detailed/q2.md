# q2: For each current NBA team, what is the average number of NBA championships won by its listed players?
## Query contract
**Natural language:** For each current NBA team, what is the average number of NBA championships won by its listed players?

**Reference SQL**
```sql
SELECT p.team, AVG(p.nba_championships) AS avg_championships FROM player p JOIN team t ON p.team = t.team_name GROUP BY p.team
```

**QuWARTS compiled SQL**
```sql
SELECT p.team, AVG(p.nba_championships) AS avg_championships FROM player p JOIN team t ON p.team = t.team_name GROUP BY p.team
```

The SQL contracts are equivalent unless the two SQL blocks visibly differ. Therefore, documented failures below are downstream of intent/compilation.

### Why QuWARTS differs
- **Pipeline stage:** Relationship and measure extraction
- **Root cause:** The shared table did not resolve each player's current team or reliably extract NBA title counts.
- **Why the system made this choice:** The raw view keeps source-backed relationship and number mentions without choosing one current fact. It is kept to avoid losing rows.
- **Why the checks did not catch it:** The join check only sees whether some keys overlap. A title count or team mention can pass type and span checks even when it belongs to the wrong time or meaning.
- **Why this query failed:** Only a small, biased set of players joins to teams and has a title count. AVG is correct over that set, but the set is wrong.

**What we saw in the run**
- In the selected player table, 62/160 team values and 114/160 nba_championships values are NULL.
- Five gold teams are missing, while Charlotte Hornets is an extra joined group not present in the gold output.
- Most aligned averages differ substantially (for example Chicago 0.3333→3.0 and San Antonio 1.2→2.3333), which is consistent with averaging a small, biased subset rather than an aggregation bug.

### Why DocETL differs
- **Pipeline stage:** Missing-value handling and exact joins
- **Root cause:** Unknown title counts were stored as -1, and player and team names were extracted separately without alias resolution.
- **Why the system made this choice:** The prompt uses -1 for unknown numbers. Each table is built in its own Map step, then SQLite joins the text exactly.
- **Why the checks did not catch it:** -1 is a valid number and team aliases are valid strings, so the Map schema accepts both. No later step masks sentinels or resolves aliases.
- **Why this query failed:** The -1 values lower averages, while names such as Celtics and Boston Celtics fail to join.

**What we saw in the run**
- The q2 player extraction has 132 rows, of which 110 have nba_championships=-1 and 53 have an empty team.
- The team table uses aliases such as Celtics, Bulls, and Mavericks while player rows use Boston Celtics, Chicago Bulls, and Dallas Mavericks; these player keys do not join.
- Negative averages such as Brooklyn=-1.0, Detroit=-0.4, and Miami=-1.0 directly show that the missing-value sentinel was aggregated as real data.
