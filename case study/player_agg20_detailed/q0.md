# q0: Among players with a known position, what is the average age at each position?
## Query contract
**Natural language:** Among players with a known position, what is the average age at each position?

**Reference SQL**
```sql
SELECT position, AVG(age) AS avg_age FROM player WHERE position IN ('Frontcourt', 'Backcourt') GROUP BY position
```

**QuWARTS compiled SQL**
```sql
SELECT "t2"."position", AVG("t2"."age") AS "avg_age"
FROM "player" AS "t2"
WHERE ("t2"."position" = 'Frontcourt' OR "t2"."position" = 'Backcourt')
GROUP BY "t2"."position"
```

The SQL contracts are equivalent unless the two SQL blocks visibly differ. Therefore, documented failures below are downstream of intent/compilation.

### Why QuWARTS differs
- **Pipeline stage:** Normalization and candidate selection
- **Root cause:** The required position buckets were never made into an enforced value map.
- **Why the system made this choice:** Bulk extraction starts without normalization hints. The raw view keeps detailed labels such as center and point guard, and this run selected that raw view.
- **Why the checks did not catch it:** Those labels are valid text and have source support. The pilot can see that the empty SQL result is stable, but it cannot know that the detailed labels should be changed.
- **Why this query failed:** The query accepts only Frontcourt or Backcourt. Since neither value exists, every player is removed before AVG runs.

**What we saw in the run**
- The selected QuWARTS player table contains 160 rows, with positions such as forward (17), point guard (14), center (14), power forward (9), and shooting guard (9), but zero Frontcourt or Backcourt values.
- Age extraction is also incomplete (91/160 rows are NULL), but that cannot affect this run because the position predicate eliminates every row first.
- The compiled SQL exactly preserves the reference position predicate; this is not an intent or SQL-compilation failure.
